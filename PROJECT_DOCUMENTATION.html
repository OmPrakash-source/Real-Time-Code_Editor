📋 Executive Summary

Project Name: Real-Time Collaborative Code Editor

Version: 1.0.0

Category: Web Application / Collaborative Tool

The Real-Time Collaborative Code Editor is a web-based platform that enables multiple users to write, edit, and compile code simultaneously in real-time. Built with modern web technologies, it provides a seamless collaborative coding experience similar to Google Docs but specifically designed for programmers. The system supports multiple programming languages (C, C++, Java, Python, JavaScript) and features dual editor screens for enhanced productivity.

🎯 Problem Statement

In modern software development and educational environments, there is a growing need for tools that enable:

  • Remote Collaboration: Developers working from different locations need to collaborate on code in real-time
  • Learning Support: Students and educators require platforms for pair programming and code review sessions
  • Instant Feedback: The ability to compile and execute code immediately without environment setup
  • Multi-Language Support: A unified platform supporting various programming languages

This project addresses these challenges by providing a comprehensive, real-time collaborative coding environment accessible through any web browser.

✨ Key Features

🤝 Real-Time Collaboration

Multiple users can edit code simultaneously with instant synchronization. Changes made by one user are immediately visible to all participants in the room.

👥 Dual Editor Support

Two independent code editor screens (Screen A & Screen B) allowing users to work on different files or compare implementations side-by-side.

🌐 Multi-Language Support

Supports 5 popular programming languages: C, C++, Java, Python, and JavaScript with syntax highlighting and auto-completion.

▶️ Code Compilation & Execution

Integrated Judge0 API enables users to compile and run code directly from the browser with custom input and detailed output.

🏠 Room Management

Create unique rooms with custom IDs or auto-generated identifiers. Share room IDs with collaborators to work together.

💾 Auto-Save & Persistence

Code is automatically saved to MongoDB with debouncing (3-second delay) to prevent excessive database writes.

🔄 Language Switching

Switch between programming languages on-the-fly. Changes sync across all users in the room automatically.

🧹 Automated Cleanup

Cron job runs every 15 minutes to delete old files (6+ hours) and empty rooms, maintaining database efficiency.

👤 User Session Management

Tracks active users in each room with automatic session creation and cleanup when users disconnect.

📊 Execution Metrics

Displays execution time and memory usage for compiled code, helping users optimize their programs.

🎨 Monaco Editor Integration

Leverages VS Code's Monaco Editor providing professional-grade features like IntelliSense and code formatting.

🔗 URL-Based Room Access

Room ID is stored in URL parameters, allowing users to bookmark or share direct links to collaboration sessions.

🗄️ Database Schema

Room Collection

Purpose: Stores room metadata and member information

Field Type Description
roomId String Unique identifier for the room (indexed)
language String Current programming language (default: 'javascript')
codeA String Code content for Screen A
codeB String Code content for Screen B
createdAt Date Room creation timestamp
members Array[String] List of user IDs currently in the room

File Collection

Purpose: Tracks file metadata and last update time for cleanup

Field Type Description
roomId String Associated room identifier (indexed)
code String Code content (legacy field)
lastUpdated Date Timestamp of last modification

UserSession Collection

Purpose: Manages active user sessions within rooms

Field Type Description
userId String Unique user identifier
roomId String Associated room identifier
socketId String WebSocket connection identifier
joinedAt Date Session start timestamp

🌐 API Endpoints

Room Management APIs

POST /room/create

Description: Creates a new collaboration room

Request Body:

{
  "roomId": "optional-custom-id",
  "language": "javascript"
}

Response:

{
  "roomId": "abc12345",
  "language": "javascript"
}

GET /room/:roomId

Description: Retrieves room metadata and initial code

Response:

{
  "room": {
    "roomId": "abc12345",
    "language": "javascript",
    "members": ["user1", "user2"],
    "createdAt": "2025-12-07T15:24:19.000Z"
  },
  "file": {
    "code": "console.log('Hello World');",
    "lastUpdated": "2025-12-07T15:30:00.000Z"
  }
}

Compilation API

POST /compile

Description: Compiles and executes code using Judge0 API

Request Body:

{
  "code": "print('Hello')",
  "language": "python",
  "stdin": ""
}

Response:

{
  "stdout": "Hello\n",
  "stderr": "",
  "time": "0.023",
  "memory": "3840"

🔌 Socket.IO Events

Client → Server Events

Event Name Payload Description
join_room {roomId, userId, language} User joins a collaboration room
code_change_A {roomId, code} Code update in Screen A
code_change_B {roomId, code} Code update in Screen B
language_change {roomId, language} Programming language changed
disconnect - User disconnects from server

Server → Client Events

Event Name Payload Description
room_joined {roomId, language, codeA, codeB} Confirmation of successful room join
code_update_A {code} Broadcast Screen A code changes to other users
code_update_B {code} Broadcast Screen B code changes to other users
language_changed {language} Notify all users of language switch
user_joined {userId} New user joined the room
user_left {userId} User left the room
error_message {message} Error notification to client

🔄 System Workflow

User Journey: Creating and Joining a Room

1
User Opens Application
Browser loads index.html and initializes Monaco editors in local mode
2
Create/Join Room
User can either create a new room (generates unique ID) or join existing room with ID
3
WebSocket Connection
Client establishes Socket.IO connection and emits 'join_room' event
4
Room Data Retrieval
Server fetches room data from MongoDB and sends existing code to client
5
Real-Time Synchronization
All code changes are broadcasted to room participants via Socket.IO
6
Code Execution
User clicks "Run" → Code sent to Judge0 API → Results displayed in output panel
7
Auto-Save
Code changes debounced and saved to MongoDB every 3 seconds

Real-Time Collaboration Flow

User A types code → Client emits 'code_change_A' event
Server receives event → Stores latest code in memory (latestCodeA Map)
Server broadcasts → Sends 'code_update_A' to all clients in the room except sender
Other clients update → Monaco editor content synchronized automatically
Debounced save → After 3 seconds of inactivity, code saved to MongoDB

Clone the Repository

cd Real-Time-Code_Editor
2
Install Dependencies 
npm install
This installs all required packages listed in package.json

Configure Environment Variables

The .env file contains:

Start MongoDB Server 
mongod
Ensure MongoDB is running on default port 27017
5
Start the Application 
npm run dev
Development server with auto-restart using nodemon
6
Access the Application

Open your browser and navigate to:

http://localhost:4000

Production Deployment

For production environments:

  • Use npm start instead of npm run dev
  • Configure MongoDB Atlas for cloud database
  • Set up process manager (PM2) for Node.js application
  • Enable HTTPS with SSL certificates
  • Configure CORS appropriately for your domain

🎮 Key Functionalities Explained

1. Debounced Auto-Save Mechanism

To prevent excessive database writes, the system implements a debouncing strategy:

  • When code changes, a timer starts (3000ms)
  • If more changes occur before timer expires, the timer resets
  • Only when user stops typing for 3 seconds, the code is saved to MongoDB
  • Separate timers maintained for Screen A and Screen B

2. Automated Cleanup Cron Job

A scheduled task runs every 15 minutes to maintain database efficiency:

  • Delete Old Files: Removes files not updated in 6+ hours
  • Delete Empty Rooms: Removes rooms with no active members
  • Clean User Sessions: Removes orphaned user session records
  • Configurable expiry duration via FILE_EXPIRY_HOURS environment variable

3. Language Mapping & Monaco Integration

Language identifiers are mapped for compatibility:

  • Application uses simple names: 'c', 'cpp', 'java', 'python', 'javascript'
  • Monaco Editor expects specific language IDs for syntax highlighting
  • Judge0 API requires language ID numbers (C=50, C++=54, Java=62, etc.)
  • Mapping ensures consistent language handling across components

4. Room Member Management

User presence tracking in collaborative rooms:

  • On join: User ID added to room's members array
  • On disconnect: User ID removed from array
  • UserSession document created with socket ID mapping
  • Broadcast events to notify other users of joins/leaves

🛠️ Challenges Faced & Solutions

Challenge: Race Conditions

Problem: Multiple simultaneous code updates causing data inconsistency

Solution: Implemented debouncing with Map-based state management to track latest code changes

Challenge: Database Bloat

Problem: Unused rooms and old files consuming storage

Solution: Created automated cron job for periodic cleanup based on timestamps

Challenge: Socket Disconnections

Problem: Users not properly removed from rooms on disconnection

Solution: Implemented disconnect event handler with proper cleanup of sessions and room members

Challenge: Editor State Sync

Problem: New users not receiving current code state when joining

Solution: Server sends complete room state (language, codeA, codeB) on 'room_joined' event

Challenge: Code Execution Security

Problem: Running arbitrary user code poses security risks

Solution: Delegated execution to Judge0 sandboxed environment via API

Challenge: Dual Editor Management

Problem: Tracking changes for two independent editors

Solution: Separate Socket.IO events and save timers for Screen A and Screen B
